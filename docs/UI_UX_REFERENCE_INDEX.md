## Reference boundaries

- **Direct evidence:** the named pages expose tracked carriers, stage or district controls, live status, start actions, step/play/reset transport, camera controls, optional follow behavior, and accuracy surfaces.
- **Documented evidence:** TokenTown explicitly describes first-visit reading stops, faster repeats, manual stepping, pan/zoom, follow, and deliberate simplification.
- **Inference:** these patterns should improve comprehension for this audience. That is a design hypothesis grounded in the binding baseline and task requirements, not a substitute for observed user research.
- **Factual boundary:** none of the three design references is used to establish a FedRAMP rule, clock, matrix, class, role, or definition.
